## Tools
- `python tools/pal/func_asm.py NAME`: target PAL disassembly for a function (names as in the INCLUDE_ASM; C++ names are mangled). If the header tag is `estimate?` or `-xfile`, check that the listing starts at a real function start (a prologue right after the previous function's `jr ra` + delay slot) before trusting it.
- `python tools/pal/check.py FILE [FUNC...]`: compiles the file with `-DVERSION_PAL` and reports MATCH/DIFF per function against PAL. The DIFF count is positional, so one extra or missing instruction makes everything after it look wrong. For real progress, diff the opcode sequences with alignment (for example difflib).
- Permuter (C files only, not C++): `tools/decomp-permuter`. `permuter_settings.toml` is generated by `python configure.py --version pal`.
- Compiler: `tools/toolchain/ee-gcc29` (EE GCC 2.9-991111-01). C flags: `-O2 -G8 -g`. C++ flags: `-O2 -G8 -x c++ -fno-exceptions -fno-strict-aliasing`.

## Conventions
- Retail compiled out most debug `printf`s: use `DPRINTF(...)` (from include/version.h) for prints that don't exist in PAL.
- PAL-only logic goes under `#ifdef VERSION_PAL`, with the original prototype code kept verbatim in `#else`. Shared headers (nalib, include/) may only change this way. After any header change, re-run check.py on every file in src/ and make sure nothing that matched broke.
- Replace an INCLUDE_ASM only when check.py says MATCH. Keep file order.
- If a function looks identical but DIFFs, its mapped address is probably wrong. Find the right one with `mips-linux-gnu-objdump -d -z -m mips:5900 -EL -j .text --start-address=.. --stop-address=.. $PAL_ISO`, note it in docs/pal_notes/, and move on.
- Never download game files.
